How ShaadiDesk fits together

One Next.js app on Vercel, one PostgreSQL database on Neon, and Cloudflare R2 for photos and backups. Everything runs on free plans, and nothing sleeps when Meena Aunty opens the link.

AppNext.js + TypeScriptPages and server code in one project. No Express.
DatabasePostgreSQL on NeonDrizzle for queries. Wakes in under a second.
FilesCloudflare R2S3 API. Photos and 30 days of backups.
HostingVercel free planname.vercel.app/priya-rahul
Code and jobsPrivate GitHub repoDeploy on push. Nightly backup job.
Team sign-inGoogle via Auth.jsGuests never sign in.

The system map

Solid arrows carry data. Dashed arrows are sign-in or messages a person sends by hand. On a phone, swipe the map sideways.

  • Every page and every save goes through lib/access before it touches the database. Hiding a button is not protection.
  • Guests never sign in. A cookie on their phone links the phone to one family.
  • The app never sends WhatsApp messages. It opens a wa.me chat and a person pushes "send".
  • Backups run on GitHub, not on Vercel, so a problem on Vercel does not stop them.
  • Real phone numbers live only in production. The laptop and preview links use fake families.

Four flows, step by step

Meena Aunty replies for the Sharma family

  1. Taps the RSVP link on the card.RSVP page
  2. No family cookie on this phone, so Screen 1 opens.lib/access
  3. Types "Sha". After 3 letters the app shows "Sharma family (Meena, Jaipur)".Production DB
  4. Types 1111. The guard checks the attempt limit and the last 4 digits, saves the device and sets the cookie.lib/access → guest_devices
  5. Screen 2 shows only Haldi and Wedding. She picks Yes 2 and Yes 4, then "Yes, submit".Server Action
  6. The database keeps one reply per family and event. If her son submitted a second earlier, his reply stays.replies (unique)
  7. The page shows "Replied" only after the server confirms the save.RSVP page

Ankit opens the money page without money access

  1. Opens /money from a saved link. The menu never showed it to him.Team pages
  2. The page asks the guard: is Ankit on this wedding's team?lib/access
  3. Yes, he is an organizer. Is his "can see money" switch on? No.Production DB
  4. Refused. The server sends no expense data at all.lib/access
  5. Ankit sees "You do not have access to this page."Team pages

Priya imports 200 families from Excel

  1. Uploads the file. The server reads it and keeps it only for the check.lib/import
  2. File validation, with no database: name, event, phone format, duplicates inside the file.validateImportFile
  3. Database validation, read only: number already used, organizer in the team, events exist.validateImportAgainstDb
  4. Errors? She downloads the error list, fixes the file and uploads again. Save stays locked until there are 0 errors. Warnings such as "no phone number" are allowed.Import page
  5. She confirms "Save 195 families?".Import page
  6. The server runs both checks again and saves all rows in one transaction. If Rohan used one of the numbers a minute ago, nothing is saved and she checks again.saveImport

What runs every night

  1. A scheduled GitHub Action starts..github/workflows
  2. It makes a copy of the production database with pg_dump.Production DB
  3. It uploads the copy, with the date in its name, to the backups bucket.R2 backups
  4. It deletes copies older than 30 days.R2 backups
  5. It checks for weddings 6 months past their date and removes their phone numbers, stay data, access requests and guest devices.FR-67

Where the code lives

Only app/ and public/ mean something special to Next.js. The other folder names are our own choice.

    w/[weddingId]/     team pages
  components/          React components
  lib/
    access/            the security guard
    db/                Drizzle schema, connection

    money/             paise ↔ ₹, Indian format
    phone/             one phone format
